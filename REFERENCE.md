# Reference

Commands, file formats and behaviour. For the non-technical walkthrough see the
[README](README.md); for the installation script an assistant should follow, see
[AGENT-INSTALL.md](AGENT-INSTALL.md).

## Install

```bash
git clone https://github.com/carsanmilcar/snowbib && cd snowbib
cp .env.example .env        # put your address in SNOWBIB_MAILTO
```

Python 3.9+. One dependency, pymupdf4llm, needed only by `convert`. Run from the clone with `python -m snowbib.<command>`,
or `pip install -e .` for the `snowbib-*` entry points.

## Configuration

| Setting | Where | Notes |
|---|---|---|
| `SNOWBIB_MAILTO` | `.env`, or a real environment variable | Contact address for OpenAlex's polite pool. Required by any command that hits the network. Never hardcode one: a clone would call the API as the repo author. |
| `SNOWBIB_VAULT` | `.env`, environment, or `--vault` | Vault root. Falls back to the current directory. |

Real environment variables override `.env`, so CI can export them instead.

## Vault layout

```
your-vault/
  papers/            one markdown note per paper, named <citekey>.md
  .snowbib/
    seen_index.json             generated by index
    ghost_meta.json             generated by cites
    citekey_openalex_map.json   generated by cites
    excluded.json               yours to write
    profile.yaml                copied by init --profile
    pdf/                        generated by fetch
    text/                       generated by convert
    cache/                      HTTP cache; safe to delete
```

Everything under `.snowbib/` except `excluded.json` is generated and will be overwritten.

## Commands

### `init` — create an empty vault

```bash
python -m snowbib.init [VAULT] [--vault PATH] [--profile NAME]
```

Creates `papers/`, `.snowbib/` and a small README. Idempotent. `--profile` copies a
field profile into the vault.

### `discover` — populate from OpenAlex

```bash
python -m snowbib.discover [--vault PATH] [--query PHRASE]... [--profile NAME]
                           [--min-year YEAR] [--min-citations N] [--limit N] [--dry-run]
```

Metadata only: it never reads a paper and never calls a language model. Repeat `--query`
to OR several phrasings. `--profile` supplies queries and the extra front matter fields
when you do not pass `--query`.

`--dry-run` reports the match count and writes nothing — **always run it first**. Above
20,000 matches without `--limit`, snowbib refuses and asks you to narrow the query.

Papers whose DOI is already in the index are skipped, so re-running later only adds what
is new.

### `cites` — reconstruct the citation graph

```bash
python -m snowbib.cites [--vault PATH] [--quiet]
```

Reads `referenced_works` for every note carrying an `openalex_id`, then writes into each
note a `cites_vault` front matter field and a `## Citations` section. References that
have no note of their own become unresolved wikilinks and their metadata is cached in
`.snowbib/` so `check` can later recognise them by DOI or title.

Slow on first run (one request per 50 notes, plus one per 50 cited works); results are
cached. Prints the most co-cited unfiled papers at the end.

### `index` — build the seen-index

```bash
python -m snowbib.index [VAULT] [--vault PATH] [--recursive] [--ignore-prefix PREFIX] [--quiet]
```

Scans `papers/*.md` and writes `.snowbib/seen_index.json`. Exits non-zero if `papers/`
does not exist, and warns loudly if the index comes out empty or notes lack front matter
— a silent zero is indistinguishable from "you have never seen this paper".

`--recursive` also walks subfolders. `--ignore-prefix` marks wikilink prefixes that are
not papers; defaults to `MOC-` (Obsidian Maps of Content), repeatable.

### `check` — filter candidates

```bash
python -m snowbib.check [CANDIDATE]... [--vault PATH] [--new-only]
```

Candidates as arguments or on stdin, one per line. Matched in this order: DOI, doi.org
URL, OpenAlex id, citekey, then title normalised to lowercase with accents and
punctuation stripped.

| Verdict | Meaning |
|---|---|
| `FILED <citekey> [status]` | A note exists |
| `DROPPED` | Listed in `excluded.json` |
| `CITED <citekey> xN` | N notes cite it; no note of its own |
| `NEW` | Unknown |

`xN` counts **notes that cite it**, not occurrences of the link. Exit status is always 0;
read the verdicts.

### `fetch` — download the open-access PDFs

```bash
python -m snowbib.fetch [--vault PATH] [--limit N] [--unscreened] [--resolver URL] [--pause S]
```

Downloads the `oa_pdf` link OpenAlex publishes for each note into
`.snowbib/pdf/<citekey>.pdf`. Verifies the bytes really are a PDF, so a landing page or
an HTML error is reported rather than saved. Handles gzip and sends browser-like headers,
since several publishers answer a bare request with 403.

Papers with no open version are counted and named, never guessed at.

**snowbib ships no way of getting closed-access papers, and will not.** Which sources are
acceptable depends on your institution and your jurisdiction, not on this tool. Two hooks
let you plug in whatever you already use:

- `--resolver URL` — a URL template containing `{doi}`, such as a library proxy.
- `--resolver-cmd CMD` — any external program, with `{doi}` and `{out}` substituted:

  ```bash
  python -m snowbib.fetch --vault ~/tda       --resolver-cmd "my-fetcher --doi {doi} --output {out}"
  ```

  It must leave a PDF at `{out}`; anything else is deleted and reported. The DOI is
  checked against the DOI grammar before it is passed to a process, and the command runs
  without a shell.

You are responsible for what you point either of them at.

### `convert` — PDF to markdown

```bash
python -m snowbib.convert [--vault PATH] [--limit N] [--overwrite]
```

Extracts the text layer into `.snowbib/text/<citekey>.md` with pymupdf4llm. Journal PDFs
are born digital, so this is instant and good enough to screen from the body rather than
the abstract; display equations do not survive, so read the PDF for those. A scanned PDF
has no text layer and is reported as `scanned` instead of producing an empty file.

### `screen` — print the screening work order

```bash
python -m snowbib.screen [--vault PATH] [--limit N] [--json]
```

Lists notes still at `status: to_read`, together with the vault profile's extraction
prompt and the batching rule. snowbib does not call a model; this is the instruction
sheet for the agent that will. `--json` for scripting.

## Note format

Only `title` is required. `doi`, `openalex_id` and `status` are used when present.
Double-quoted, single-quoted, bare and folded YAML values all work, and CRLF files are
handled.

```yaml
---
type: paper
status: to_read          # to_read | reference | applied | discarded
title: "Topology and data"
authors: "Gunnar Carlsson"
year: 2009
venue: "Bulletin of the AMS"
doi: "10.1090/S0273-0979-09-01249-X"
openalex_id: "W2963757470"
cited_by: 3521
oa_pdf: "https://..."
topics: ["Topological and Geometric Data Analysis"]
cites_vault: ["[[edelsbrunner2002topological]]"]   # written by cites
cites_n: 42                                        # written by cites
---
```

Citekeys are `lastname + year + first meaningful title word`, with a letter suffix on
collision. Duplicate records in OpenAlex can produce near-twins like
`zomorodian2004computing` and `zomorodian2004computinga`;
`citekey_openalex_map.json` keeps the id so you can reconcile.

## Ledgers

`excluded.json` — papers you decided against, so they come back `DROPPED` rather than
`NEW`:

```json
{"ids": ["W1789155650"], "dois": ["10.1002/met.12"]}
```

`ghost_meta.json` and `citekey_openalex_map.json` are written by `cites`: metadata for
papers known only as citations, so `CITED` can be reached by DOI or title and not just by
citekey.

## Profiles

A profile says what is worth extracting in a field. `profiles/nwp.yaml` asks for reported
metrics with their baseline and lead time; `profiles/math.yaml` for what is proved, under
which hypotheses, with which technique.

```yaml
name: mathematics
openalex:
  field: fields/26            # OpenAlex field id, optional
  queries:
    - "persistent homology"
  min_year: 2000
fields:                       # extra front matter on every note
  technique: []
  msc: []
screening_prompt: >
  What to extract from the body.
```

The reader handles nested mappings, `- ` lists, folded `>` blocks, scalars and `#`
comments — not arbitrary YAML. Keep to the shape above.

## Limits

- Title matching is exact after normalising, not fuzzy.
- OpenAlex publishes `referenced_works` for roughly half of all works: 850,355 of
  1,564,988 works in Mathematics from 2015 on (54%), 890,248 of 2,085,158 in Earth and
  Planetary Sciences (43%). A `NEW` verdict does not prove nothing cites it.
- Text search is blunt: add `--min-citations` or a profile `field` to cut noise.
- **Queries must be in English.** OpenAlex indexes titles and abstracts almost entirely in
  English; the same field searched in another language returns a few stray works rather
  than thousands. `discover` warns when a query returns fewer than 50 matches.
- OpenAlex has no MSC codes, so mathematical subfields are delimited more coarsely than
  in zbMATH or MathSciNet.
- snowbib downloads no papers.

## Tests

```bash
python -m unittest discover -s tests
```

35 tests, no network. Every case is a bug that shipped once: front matter that is not
double quoted, CRLF line endings, counting link occurrences instead of citing notes, a
vault path with brackets.
